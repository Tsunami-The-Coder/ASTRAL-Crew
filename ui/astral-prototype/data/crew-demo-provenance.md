# Crew dashboard replay provenance

The mission dashboard's embedded `mission-demo-data` is a backend
`internal-review-v1` JSON export. It is synthetic, not a live sensor feed. It
contains two stored timestamps, five synthetic crew records, shared cabin data,
versioned backend/multimodal findings, and a synthetic review entry. No extra
chart samples are invented; null values remain unavailable.

The replay was generated by running the actual voice personal-baseline pipeline
on generated audio and the actual wearable feature extraction/research model on
generated wrist arrays, then storing the result through the backend mission log.
Voice source: c6caec4267f56a6adb1a20fc6eb4fa076eb7f56e. Wearable source:
b61174e32cebe1ffe4a91fb80eaf3d32efd0f16d, artifact wesad-wrist-logistic-v1.
This establishes software compatibility on synthetic signals, not stress accuracy.
AST-05 is represented explicitly but current producers do not support that ID.

Replay analysis clock: 2026-11-15T12:00:00Z. Freshness shown is the recorded
snapshot freshness at that clock, not a claim of current live monitoring.
Imported exports remain read-only in the UI and are not uploaded or automatically
persisted. Personal browser check-ins are a separate sandbox; they do not update
the mission replay or the Python database.

The NASA OSD-575 biology view remains separate and has four real pseudonymous
research crew codes. No fifth participant is fabricated in that research dataset.
The WESAD feature sandbox remains separate; clearing a required numeric input
prevents scoring rather than converting it to zero.

No clinical thresholds, model calibration, causal conclusions, spacecraft actions,
or authenticated crew review are introduced by the display. The shared data
contract and producer sources were not modified. UI handoff uses an internal
candidate export that still needs team review.
